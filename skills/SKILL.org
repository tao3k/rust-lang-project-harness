#+title: ASP Rust Native Syntax Playbook

* Role

Use the Rust provider as the native-syntax authority for Rust source.  The
public discovery surface is one bounded command:

#+begin_src sh
asp rust search playbook '<question>' --workspace .
#+end_src

The playbook composes four internal stages in a fixed order:

1. ripgrep candidate acquisition;
2. Rust native-syntax owner, selector, byte-range, query-key, and relation
   projection;
3. resident Tantivy lexical ranking;
4. ASP Python Graph correlation.

These stages are implementation facts, not separate public commands.  Do not
ask the agent to select or sequence them.

* Playbook intents

Use the smallest intent that expresses the task:

#+begin_src sh
asp rust search playbook 'where is request admission decided' \
  --intent conceptual --workspace .

asp rust search playbook 'callers and tests for RuntimeSearchServiceHandle' \
  --intent relationship --workspace .

asp rust search playbook 'exact declaration of RuntimeSearchServiceHandle' \
  --intent exact-literal --workspace .

asp rust search playbook 'prove no legacy SearchOperation Pipe remains' \
  --intent absence-proof --coverage complete --workspace .
#+end_src

Use =--scope owner:<path>= only when the owner is already known.  A scoped
playbook still returns native-syntax projections and never degrades into an
owner-only lookup.

* Receipt contract

Accept a completed playbook only when its version-1 receipt proves all of the
following:

- the fixed four-stage plan completed;
- every projected owner has a content digest;
- every native-syntax projection has canonical selectors, proper byte ranges,
  and nonempty query keys;
- every relation is bound to projected owners;
- the decision owner set equals the native-syntax owner set;
- stage and generation digests are present.

An owner path without parser projection is not usable evidence.  A partial,
unknown, malformed, or cross-generation receipt is terminal and must not be
silently widened to raw source reads.

* Exact materialization

After the playbook returns a canonical selector, materialize only that selector:

#+begin_src sh
asp rust query --selector '<rust-selector>' --projection source --workspace .
#+end_src

Use =--projection callable-skeleton= when a callable outline is sufficient.
Do not replace a selector with an approximate file dump.

* Editing and validation

Edit only the owner selected by the receipt.  Route Rust build, test, check,
clippy, and formatting commands to ASP Testing.  Preserve the playbook
generation and selector identities in the validation receipt so the result can
be tied back to the evidence used for the change.

* Removed surfaces

=search prime=, =search owner=, =search lexical=, =search ingest=, and =search
pipe= are removed public operations.  They are not aliases and must not appear
in agent guidance, recovery messages, or generated next commands.
